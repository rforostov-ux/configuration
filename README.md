# Эмулятор оболочки ОС

Эмулятор командной строки UNIX-подобной ОС с графическим интерфейсом
(Python, tkinter). Разрабатывается по этапам:

| Этап | Содержание | Состояние |
|---|---|---|
| 1. REPL | окно, парсер с `$VAR`, заглушки `ls`, `cd`, команда `exit` | готов |
| 2. Конфигурация | параметры командной строки, стартовый скрипт | готов |
| 3. VFS | виртуальная файловая система из XML, команда `vfs-info` | готов |
| 4. Основные команды | `ls`, `cd` по VFS, `tail`, `tac`, путь в приглашении | готов |
| 5. Дополнительные команды | `rm` | впереди |

## Требования

- Python 3.8 или новее (tkinter входит в стандартную установку)
- Внешние зависимости не нужны

## Сборка и запуск

Сборка не требуется: проект на Python запускается из исходников.

```
python src/main.py [--vfs ПУТЬ] [--script ПУТЬ]
```

Готовые обёртки: `run.bat` (Windows) и `./run.sh` (Linux/macOS) передают
все параметры в `src/main.py`.

## Параметры командной строки

| Параметр | Значение |
|---|---|
| `--vfs ПУТЬ` | путь к физическому расположению VFS |
| `--script ПУТЬ` | путь к стартовому скрипту |
| `-h`, `--help` | справка |

- Параметры необязательны, порядок любой, допустима форма `--имя=значение`.
- Путь с пробелами берите в кавычки: `--vfs "my dir/disk.xml"`.
- Сокращения (`--vf`) и позиционные аргументы не поддерживаются.
- При неверных параметрах (неизвестный параметр, нет значения) печатается
  справка, окно не открывается, код выхода равен 2.
- Имя VFS в заголовке окна — имя файла из `--vfs` без каталога и
  расширения (`data/disk.xml` даёт `disk`). Без `--vfs` имя равно `vfs`.
- Файл VFS загружается при запуске (см. раздел «Виртуальная файловая
  система»).

## Отладочный вывод параметров

При запуске в окне сразу выводятся все заданные параметры:

```
Эмулятор оболочки. Для выхода введите exit.
[debug] параметры запуска:
[debug]   --vfs    = data/disk.xml
[debug]   --script = examples/startup_ok.emu
[debug]   имя VFS  = disk
```

Незаданный параметр помечается как `<не задан>`.

## Стартовый скрипт

Параметр `--script` задаёт текстовый файл (UTF-8, допускается BOM) с
командами эмулятора, по одной в строке.

- Пустые строки пропускаются. Строка с `#` в начале слова — комментарий.
- Для каждой строки в окне показывается ввод (с приглашением) и вывод,
  как будто команды вводит пользователь.
- **Скрипт останавливается на первой ошибке** (неизвестная команда,
  синтаксическая ошибка, неверные аргументы). В окно выводится сообщение
  с именем файла и номером строки, остальные строки не выполняются.
  Окно остаётся открытым: дальше можно работать вручную.
- Команда `exit` в скрипте тоже останавливает его и закрывает окно;
  код выхода процесса берётся из `exit`.
- Если файл скрипта не найден, не читается или не в UTF-8, выводится
  сообщение `ошибка скрипта: ...`, окно остаётся открытым.

Пример диалога для `examples/startup_error.emu` (с `--vfs examples/vfs/deep.xml`):

```
user@host:/$ # Стартовый скрипт с ошибкой: после третьей команды ...
user@host:/$ ls
home/
readme.txt
user@host:/$ cd /
user@host:/$ unknown_command arg1 arg2
unknown_command: команда не найдена
скрипт остановлен: ошибка в examples/startup_error.emu, строка 4
```

## Виртуальная файловая система (VFS)

VFS задаётся параметром `--vfs` и загружается в память один раз при
запуске. Все операции выполняются только в памяти: XML-файл на диске
никогда не изменяется. Без `--vfs` создаётся пустая VFS, в которой есть
только корневой каталог `/`.

### Формат XML

```xml
<vfs>
  <dir name="home">
    <dir name="user">
      <file name="notes.txt">первая строка
вторая строка</file>
      <file name="logo.png" encoding="base64">iVBORw0KGgo=</file>
    </dir>
  </dir>
  <file name="readme.txt">Привет из VFS</file>
</vfs>
```

- Корневой элемент — `<vfs>`, он соответствует каталогу `/`.
- `<dir name="...">` — каталог, внутри могут быть другие `<dir>` и `<file>`.
- `<file name="...">` — файл; текст внутри тега — его содержимое.
  С атрибутом `encoding="base64"` содержимое считается двоичным и
  декодируется при загрузке.
- Имя обязательно, не может быть пустым, содержать `/`, равняться `.` или
  `..` и не может повторяться внутри одного каталога.

### Ошибки загрузки

При ошибке окно всё равно открывается, сообщение выводится красным сразу
после отладочного вывода, а эмулятор работает с пустой VFS.

| Ситуация | Сообщение |
|---|---|
| файла нет | `ошибка VFS: disk.xml: файл не найден` |
| не XML или XML с ошибкой | `ошибка VFS: disk.xml: неверный формат XML (строка 7)` |
| корень не `<vfs>` или неизвестный тег | `ошибка VFS: неизвестный элемент <folder>` |
| нет атрибута `name` | `ошибка VFS: каталог /home: элемент <file> без атрибута name` |
| недопустимое имя | `ошибка VFS: каталог /home: недопустимое имя «a/b»` |
| имя повторяется | `ошибка VFS: каталог /home: повторяется имя user` |
| неверные данные base64 | `ошибка VFS: файл /logo.png: неверные данные base64` |
| другая кодировка | `ошибка VFS: файл /a.bin: неизвестная кодировка hex` |

### Служебная команда vfs-info

Показывает, какая VFS загружена (каталоги считаются без корня):

```
user@host:/$ vfs-info
VFS: deep
источник: examples/vfs/deep.xml
каталогов: 6, файлов: 5
```

### Примеры

| Файл | Назначение |
|---|---|
| `examples/vfs/minimal.xml` | минимальная VFS: только корень |
| `examples/vfs/files.xml` | несколько файлов в корне, в том числе двоичный (base64) |
| `examples/vfs/deep.xml` | более 3 уровней вложенных каталогов и файлов (6 каталогов, 5 файлов) |
| `examples/vfs/broken.xml` | XML с ошибкой — для проверки сообщения об ошибке |
| `examples/startup_vfs.emu` | стартовый скрипт: команды этапов 1–3, VFS и ошибка (`exit` — в `startup_exit.emu`) |

```
run.bat --vfs examples/vfs/deep.xml --script examples/startup_vfs.emu
```

## Окно

Окно выглядит как терминал: сверху вывод, снизу строка ввода и справа
кнопка «Выполнить». Команду запускает Enter или кнопка. Ошибки
выделяются красным. Приглашение показывает текущий каталог VFS.

## Команды

| Команда | Что делает |
|---|---|
| `ls [путь]` | содержимое каталога (по умолчанию текущего) |
| `cd [путь]` | смена текущего каталога; без аргумента — корень `/` |
| `tail [-n N] файл` | последние N строк файла (по умолчанию 10) |
| `tac файл` | строки файла в обратном порядке |
| `exit [код]` | закрывает окно, процесс завершается с указанным кодом |
| `vfs-info` | служебная: имя VFS, источник, число каталогов и файлов |

На этапе 1 `ls` и `cd` были заглушками; начиная с этапа 4 они работают с
VFS.

## Работа с файлами: ls, cd, tail, tac

Пути бывают абсолютные (`/home/user`) и относительные (`user/notes.txt`,
считаются от текущего каталога). `.` — текущий каталог, `..` — родитель;
выше корня подняться нельзя. Приглашение показывает текущий каталог:
`user@host:/home/user$`.

| Команда | Подробности |
|---|---|
| `ls [путь]` | имена по алфавиту, каталоги выводятся с `/` на конце; для файла выводит его имя |
| `cd [путь]` | переходит в каталог; `cd ..` — на уровень вверх |
| `tail [-n N] файл` | последние N строк; `-n 0` — ничего, N больше числа строк — весь файл |
| `tac файл` | строки файла от последней к первой |

Пример (`--vfs examples/vfs/deep.xml`):

```
user@host:/$ ls
home/
readme.txt
user@host:/$ cd home/user
user@host:/home/user$ ls
logo.png
notes.txt
user@host:/home/user$ tac notes.txt
вторая строка
первая строка
user@host:/home/user$ tail -n 1 notes.txt
вторая строка
user@host:/home/user$ cd ../..
user@host:/$
```

### Ошибки команд

| Ситуация | Сообщение |
|---|---|
| путь не существует | `ls: nope: нет такого файла или каталога` |
| `cd` в файл, путь через файл | `cd: readme.txt: не каталог` |
| `tail`/`tac` для каталога | `tac: home: это каталог` |
| `tail`/`tac` для двоичного файла | `tail: logo.png: двоичный файл` |
| неверное N у `tail` | `tail: -n abc: требуется неотрицательное число` |
| нет имени файла или лишние аргументы у `tail`/`tac` | `tac: требуется один аргумент — файл` |
| больше одного пути у `ls`/`cd` | `ls: слишком много аргументов` |
| ключ, кроме `-n` у `tail` | `ls: неизвестный ключ -l` |

### Стартовый скрипт этапа 4

`examples/startup_commands.emu` проверяет все режимы `ls`, `cd`, `tail`,
`tac` и заканчивается ошибкой (`tac /home`). Так как скрипт
останавливается на первой ошибке, остальные ошибки по одной показывают
скрипты из `examples/errors/`. Все они запускаются с `deep.xml`:

```
run.bat --vfs examples/vfs/deep.xml --script examples/startup_commands.emu
scripts\test_commands.bat
```

## Парсер

- Пробелы разделяют аргументы.
- `$VAR` и `${VAR}` раскрываются значением переменной окружения реальной
  ОС; неопределённая переменная даёт пустую строку.
- `"двойные кавычки"` сохраняют пробелы и раскрывают переменные.
- `'одинарные кавычки'` сохраняют текст как есть, без подстановок.
- `#` в начале слова начинает комментарий до конца строки; внутри слова
  и в кавычках `#` — обычный символ.

## Обработка ошибок

- неизвестная команда: `foo: команда не найдена`;
- незакрытая кавычка, нет `}` в `${`, неверное имя в `${}`:
  `синтаксическая ошибка: ...`;
- ошибки команд `ls`, `cd`, `tail`, `tac` (см. «Ошибки команд»);
- лишние аргументы у `exit`, нечисловой аргумент у `exit`;
- ошибки стартового скрипта (см. выше) и параметров командной строки;
- ошибки загрузки VFS (см. раздел «Виртуальная файловая система»).

В Windows переменной `HOME` обычно нет, используйте `$USERPROFILE` и
`$USERNAME`.

## Проверка параметров скриптами реальной ОС

В папке `scripts/` лежат скрипты, которые запускают эмулятор с разными
параметрами. Для каждого есть версия для Windows (`.bat`) и для
Linux/macOS (`.sh`). Стартовые скрипты эмулятора лежат в `examples/`.

| Скрипт | Что проверяет |
|---|---|
| `test_params` | все комбинации `--vfs` и `--script`, обе формы записи |
| `test_script_errors` | ошибки скрипта, нет файла, неверные параметры |
| `test_exit_code` | коды выхода процесса (`exit 3`, `exit 5`, обычное закрытие) |
| `test_vfs` | все варианты VFS подряд: каждый из скриптов ниже и запуск без `--vfs` |
| `test_vfs_minimal` | минимальная VFS (только корень) |
| `test_vfs_files` | несколько файлов в корне, в том числе двоичный (base64) |
| `test_vfs_deep` | глубокая VFS: более 3 уровней каталогов и файлов |
| `test_vfs_errors` | ошибки загрузки: нет файла, повреждённый XML, не XML |
| `test_commands` | этап 4: все режимы `ls`, `cd`, `tail`, `tac` и каждая ошибка отдельно |

Запуск (из любой папки):

```
scripts\test_params.bat          (Windows)
./scripts/test_params.sh         (Linux/macOS)
```

Каждый вызов эмулятора открывает окно; закройте его или введите `exit`,
чтобы перейти к следующему шагу. Интерпретатор можно сменить переменной
окружения `PYTHON`.

## Тесты

Модульные тесты (`unittest`), запускать из корня репозитория:

```
python -m unittest discover -s tests -t .
```

## Структура проекта

```
src/
  main.py        точка входа
  config.py      параметры командной строки, отладочный вывод
  startup.py     сообщения при запуске (отладка + скрипт)
  script.py      выполнение стартового скрипта
  gui.py         окно (tkinter)
  shell.py       выполнение команд
  cmd_parser.py  парсер строки и раскрытие переменных
  vfs.py         модель VFS в памяти, загрузка из XML, поиск по путям
tests/           модульные тесты
examples/        стартовые скрипты эмулятора (.emu)
  vfs/           примеры VFS в XML
  errors/        скрипты, каждый показывает одну ошибку команд этапа 4
scripts/         скрипты реальной ОС для проверки параметров и VFS
run.sh, run.bat  запуск эмулятора
```

Окно (`gui.py`) не знает про команды, а оболочка (`shell.py`) — про окно:
оболочка и скрипт возвращают списки сообщений, окно их показывает.

## Коммиты

Сообщения коммитов оформляются по спецификации Conventional Commits:
`тип(область): описание`, например `feat(config): ...`, `fix(parser): ...`.
